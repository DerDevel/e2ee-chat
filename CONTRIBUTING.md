# Contributing

Спасибо за интерес к проекту!

## Быстрый старт

```bash
git clone https://github.com/DerDevel/e2ee-chat.git
cd e2ee-chat
make build   # сборка
make test    # тесты
make lint    # golangci-lint (0 issues — обязательное условие)
```

Полный e2e-прогон реальных бинарей (нужны `python3` и `openssl`):

```bash
make smoke
```

## Правила

1. **Перед пушем** локально должны быть зелёными:
   ```bash
   make fmt vet lint race
   ```
   CI проверяет то же самое + gofmt-чек, и он обязателен для merge.

2. **Новые фичи — с тестами.** Для логики relay достаточно модульных тестов на
   `fakeStore`; для протокольных изменений — обновите
   `server/integration_test.go` (полный прогон через реальный TLS+gRPC).

3. **Криптографические изменения** (всё в `internal/e2ee/`) — отдельная тема:
   - любое изменение деривации ключей, формата транскрипта или SAS меняет
     протокол и требует обновления соответствующих атак-тестов
     (`TestSubstitutedKEMKeyDesynchronizesSAS`, `TestTransplantedCiphertextDesynchronizes` и др.);
   - описывайте мотивацию изменения в терминах модели угроз — что именно
     новая конструкция предотвращает.

4. **Безопасность.** Если нашли уязвимость — см. [SECURITY.md](SECURITY.md),
   не открывайте публичный issue.

5. **Стиль Go**: стандартный `gofmt`; комментарии к экспортируемым сущностям —
   на английском, пользовательские строки интерфейса — на русском (как в
   остальном коде).

## Что особенно нужно

- Независимый крипто-ревью `internal/e2ee`
- Идеи по UX TUI (ввод, история, уведомления)
- Деплой: systemd-юниты, Dockerfile для сервера
- Локализация интерфейса

Пул-реквесты: короткое описание + ссылка на issue (если есть). Для крупных
изменений сначала откройте issue с предложением.
